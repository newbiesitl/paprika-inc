# Paprika Inc 0.3.2

Stable release combining the reviewed icon containment fix, optional engineering
review pack, and task/reporting and initialization guidance.

- Each public skill carries its icon inside its own assets directory. Package
  validation rejects escaping, missing, symlinked, duplicate or tampered icons.
- Optional engineering-core adds one project review skill with pinned provenance
  and notices. Multi-pack installation preserves existing research records and
  validates installed-file integrity and interrupted-install recovery.
- Company initialization guidance recommends Coordinator and Release Engineer
  responsibilities, dedicated company boards, verified receiver continuity and
  authorized completion/blocker reports to the dispatching coordinator.
- Researcher guidance recommends GPT-6 Astra with extra-high effort where the
  selected host supports it, while preserving the owner's actual model choice.
  Profile edits do not change an existing chat; requested and applied settings
  remain separate. Automatic model-profile consumption is not implemented.

## Compatibility and verification limits

Node.js 24+ and Python 3.10+ remain the local helper/build prerequisites. Messenger
stays pinned at 1.6.0 (776efe80eb801ca850b64516c003325833157240);
research, Karpathy and Ponytail sources retain their reviewed immutable pins.
No service deployment, dependency upgrade or receiver automation is included.

The icon containment defect is fixed in source and packages. Actual picker and
message-header rendering and the fallback-icon root cause remain unverified;
real-client testing is still required. Packaging checks do not establish review
quality, authenticated service access or managed lifecycle enforcement.

## Upgrade and recovery

Update the existing plugin identity using the supported account or local plugin
workflow. Preserve any existing App/service binding, private journals, company
state and project skills; do not create a duplicate plugin or migrate services.
Project skill updates remain explicit and integrity-checked.

Keep the previous source/artifact and account release available. To roll back,
prepare a supported guarded update from the previous compatible content with a
new version, preserving current private state and bindings. Do not overwrite
published tags/artifacts or rewind work inventories and receiver state.
