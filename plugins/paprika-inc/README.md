# Paprika Inc — local MVP kit

Version 0.3.0. Includes [Paprika Inc](skills/paprika-inc/SKILL.md) and [setup](skills/setup-paprika-inc/SKILL.md), a contained Node.js 24+ helper, the navy Paprika icon and pinned Messenger component/license. The MVP discusses/authors generic company files, protects Git checkout destinations and drives a sequential supported-native-host project-chat bootstrap. Git is needed for checkout; no additional npm dependencies or separate Messenger product is required.

Inc adds only its own product identity and two Inc-namespaced skills. It does not install another Messenger product, icon or command. For Inc-only or Messenger-already-installed onboarding, version distinctions, shared-service preservation and the pending fresh-chat UI acceptance check, see [coexistence](skills/setup-paprika-inc/references/coexistence.md). A required backend App may separately appear as Paprika Service; this kit declares none.

Ask `$paprika-inc help`, “show company status”, “list role definitions”, or `$setup-paprika-inc`. With an explicitly selected local repository, the helper reads its manifest/contracts and prepares a plan. See [command reference](skills/paprika-inc/references/commands.md) and [definition profile](skills/paprika-inc/references/definition-profile.md).

The default owner-neutral kit has no MCP server, required App or always-on process. An optional private bound export references exactly one existing Paprika Service App; it never creates another App/service or proves authentication. Installation/connection use supported host tools only when requested. Hosts without the required local project tools receive a local-Codex handoff. See [the full workflow and binding report](skills/setup-paprika-inc/references/mvp-workflow.md).

Setup/init defaults to a plan. Explicit author/write/checkout/bootstrap commands implement the human-requested MVP; role onboarding initially reads/reports only. One bootstrap at a time is a limitation, not enforced singleton/concurrency safety. Advanced registry/failover/transfer/self-adoption and background receiving are deferred. Fixtures/package validation are not live installation, project/chat/UI or whole-workflow certification. See [boundaries](skills/setup-paprika-inc/references/boundaries.md) and [third-party notices](THIRD_PARTY_NOTICES.md).

Optional [research-core](skills/setup-paprika-inc/references/research-core.md)
supports `skills plan/install/status` and manifest skill_sets references. Its four
selected skills are internal resources until explicitly installed into a chosen
Git project's .agents/skills/. Integrity, local dependencies and unverified access
are separate. Optional paid/PDF/figure/Scholar features are disabled by default.
Only the two Inc entry skills are public plugin exports; no upstream plugin is
registered.
